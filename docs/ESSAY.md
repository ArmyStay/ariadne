# Ariadne — 300-word essay

Ariadne is a trip-scoped spend memory for the moment that matters: you are tired, offline, and holding a receipt you will forget by nightfall. It is not an expense tracker and not a travel app. The shutter is the whole capture gesture—one photo, under two seconds—while amounts, categories, and notes wait for Nightfall, when the day becomes a calm card stack finished in a few taps.

The architecture keeps that promise in code. Kotlin Multiplatform puts domain, queue, extraction, FX, search, store, design system, and UI in shared modules; platform code is confined to camera, file storage, clipboard, drivers, and recognizers. Money is modeled as `Long` minor units, conversion is rounded once at the FX boundary, and every capture moves through a total queue state machine (`QueueState.next`) so illegal transitions are refused rather than papered over. Extraction is best effort: on Android, on-device ML Kit text recognition, and on desktop, the Tesseract CLI binding, feed the shared receipt parser; when OCR fails or finds nothing usable, the capture remains queued with an editable blank field instead of becoming an error.

The repository treats evidence as part of the product. A claims-to-code table maps promises to implementations, receipt-parser fixtures exercise real receipt shapes, and the migration story is written from experience: `openOrMigrate` decides from columns present (not only `PRAGMA user_version`), repairs partially upgraded databases, and is validated against real schema shapes rather than invented fixtures. The UI follows a single restrained design system with reduced-motion support, no red states, and a Nightfall flow designed for speed—including batch confirmation of captures that already have amounts. The bottom bar is Home, Timeline, Trip and Stats; the trip page is the one screen that keeps dates, progress and the card together, and it is the first tab, because the trip is the product.

One moment of honesty about the migration path, because it is the least glamorous code in the repo and a judge reading the essay is an engineer: the first migration was lost on a real device — an early build ran `create` without writing the version, and an existing install then opened fine and the INSERT threw inside a swallowed coroutine. `openOrMigrate` now decides from the columns actually present, and the lesson is encoded as a gate that fails when the app would fail. A migration path that fails when the app would fail is the kind of detail senior engineers keep for decades.

What remains is human verification: a green Gradle run on the four targets (Android, desktop, iOS, Wasm), the six curated hero shots in the README, and a phone video proving the camera-to-Nightfall path on hardware. Ariadne’s bet is simple: a memory kept locally, honestly, and finished at day’s end.
