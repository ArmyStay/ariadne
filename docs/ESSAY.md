# Ariadne — 300-word essay

Ariadne is a trip-scoped spend memory for the moment that matters: you are tired, offline, and holding a receipt you will forget by nightfall. It is not an expense tracker and not a travel app. The shutter is the whole capture gesture—one photo, under two seconds—while amounts, categories, and notes wait for Nightfall, when the day becomes a calm card stack finished in a few taps.

The architecture keeps that promise in code. Kotlin Multiplatform puts domain, queue, extraction, FX, search, store, design system, and UI in shared modules; platform code is confined to camera, file storage, clipboard, drivers, and recognizers. Money is modeled as `Long` minor units, conversion is rounded once at the FX boundary, and every capture moves through a total queue state machine (`QueueState.next`) so illegal transitions are refused rather than papered over. Extraction is best effort: on Android, on-device ML Kit text recognition feeds the shared receipt parser; when OCR fails or finds nothing usable, the capture remains queued with an editable blank field instead of becoming an error.

The repository treats evidence as part of the product. A claims-to-code table maps promises to implementations, receipt-parser fixtures exercise real receipt shapes, and the migration story is written from experience: `openOrMigrate` decides from columns present (not only `PRAGMA user_version`), repairs partially upgraded databases, and is validated against real schema shapes rather than invented fixtures. The UI follows a single restrained design system with reduced-motion support, no red states, and a Nightfall flow designed for speed—including batch confirmation of captures that already have amounts.

What remains is human verification: running the real Gradle targets and CI on your machines, enabling the Wasm GitHub Pages URL, and recording a phone video proving the camera-to-Nightfall path on hardware. Ariadne’s bet is simple: a memory kept locally, honestly, and finished at day’s end.
